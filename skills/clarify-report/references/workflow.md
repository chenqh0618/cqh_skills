# 报告工作流

围绕一个明确的分析任务，生成标准 GitHub Markdown 报告。默认面向有一定教育背景、非本领域专家的读者，使用通俗中文，解释理解结果所必需的方法和术语；篇幅随任务复杂度调整。用户指定的读者、详略、语言和输出位置优先。

## 1. 界定任务并核实证据

- 从调用参数、当前任务和已有文件确定要回答的问题、比较对象及结果目录。可整理先前会话留下的分析，不局限于当前对话记录；只读取与指定任务有关的材料。
- 阅读相关源表、图、运行记录及必要代码。代码说明方法，实际运行产物证明执行和结果；对话用于定位，不能替代结果文件。
- 核对数据子集、比较方向、分组、关键参数和运行版本。多个版本并存时，根据任务指定和运行记录定位，不能仅取修改时间最新的文件。关键版本冲突无法解决时，标注受影响结果未验证，继续整理其他可核实内容。
- 在报告的数据与方法部分简要记录任务标识、所用结果版本或运行记录；未知信息写明“未知/未记录”。每个关键结论旁用相对链接指向源表、图或运行记录，必要时注明 sheet、行列、比较名称或筛选条件，便于回查数字。
- 图片缺失但源表可核实时，改用表格或已有有效图；需要重新绘图时只做同一结果的展示转换，并保留源数据链接。关键证据无法核实时，标注未验证或撤下对应结论。分组、标识符、单位等冲突未解决前，不交付依赖它们的确定性结论。

## 2. 表达科学结果

- 涉及统计比较时，说明推断单位，区分 donor/sample 等独立重复数量与 cell/spot/read 等观测数量；写清实际比较方向、单位和已使用的关键调整因素。
- 关键结果优先呈现已有的效应大小、不确定性、跨样本一致性及生物学相关性；若报告 p value 或 FDR，保留其检验、校正和阈值上下文，不以显著性替代效应解释。
- 区分数据观察、统计关联、候选机制和因果证据。影响判断的限制贴近对应结果，解释最可能改变判断的混杂因素或替代解释。
- 允许阴性结果、不确定结果和“现有证据不足以判断”成为主要结论。未做的敏感性分析、统计检验或实验验证如实说明，不为补齐报告自动新增分析。
- 生物学背景与本次发现分开表述；外部方法或机制依据需要引用时，查阅可核实的一手来源。不存在的引用、未确认的工具全称不得补写。纯绘图或格式任务只说明必要的数据语义与展示变换。

## 3. 组织正文

以下是可合并、可裁剪的默认顺序，不规定章节数量：

1. **问题与简要回答**：说明本任务要判断什么，以及证据当前支持的答案。
2. **数据与方法**：交代分析设计、关键数据范围和必要方法直觉；背景只写到足以理解问题，避免重复讲解 pipeline 和算法。
3. **结果解释**：围绕关键判断，按“看到了什么—图表怎么读—能够说明什么”展开。保留关键数字和证据链接，不罗列所有产物。
4. **限制与下一步**：归纳影响决策的边界，以及真正能减少关键不确定性的下一步。无需为凑结构提出后续分析。
5. **缩写词与术语表**：放在末尾，覆盖正文实际使用的英文缩写和理解结果所需的术语。

术语首次出现时用一句话解释，类比只在有助于理解且不会改变含义时使用。词表采用“术语/缩写、英文全称（适用时）、中文名称或释义、简要解释”；正规缩写给出经核实的全称，工具专名和基因符号不强行展开。无适用全称写“—”，待核实全称明确标注，不因大写形式自动认定是缩写。

## 4. 保存与检查

- 结果目录优先采用用户指定目录，否则采用所选任务的实际输出目录；多个任务目录时聚焦本任务，不自动扩大到整个项目。无法推断时使用当前目录，并简要注明该默认值。
- 默认写入 `<结果目录>/report/analysis_report_<task>_YYYYMMDD.md`。若传入的目录已经是 `report/`，直接使用，避免重复嵌套。`<task>` 优先使用已有任务标识，否则使用结果目录名，替换路径分隔符及不适合文件名的字符；日期取系统本地日期。
- 同名文件默认保留，新文件追加 `_v02`、`_v03` 等未占用序号。用户明确要求更新指定报告时才覆盖该报告。尊重用户指定的文件名和路径，保留原始数据和分析输出。
- 只交付 Markdown 报告，不另外生成 HTML、索引或重复摘要文件。所有本地图表及证据链接相对于报告文件本身解析；含空格等字符的链接使用正确的 Markdown/URL 转义。
- 检查关键数字及比较方向与源文件一致，结论强度与证据一致，术语解释无虚构，所有本地链接指向存在的文件。引用图前实际查看图片，核对坐标轴、颜色、标签及图注，不能根据文件名猜图的内容。
- 交付报告的绝对路径，简要说明回答的问题及仍影响判断的未验证项，无需汇报章节或词条数量。

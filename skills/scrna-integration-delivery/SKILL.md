# scRNA 整合注释交付

将一个具体 scRNA 数据集的整合、聚类、注释及状态结果组织成可浏览、可复核的交付。一个技能入口服务于全数据集、谱系、celltype 或明确的细胞组合，实际对象和分析方法由项目决定。

## 调用与范围

只有用户明确指名 `$scrna-integration-delivery` 或要求使用本 skill 时才应用。同一任务的续跑沿用该选择；历史调用、其他文档的引用或普通 scRNA 分析请求不触发新任务自动套用。Codex 的 `agents/openai.yaml` 已配置关闭隐式调用。

先根据当前指令与持续有效的授权确定任务：

| 用户要求 | 执行范围 |
| --- | --- |
| 整理目录、结果文件或交付规范 | 核对现有产物，整理目录／索引／说明；不由此启动补图或重算 |
| 补绘或重绘指定图表 | 复用适配的对象和结果，完成所需聚合、marker 排名或评分及绘图；只展开指定类别 |
| 完整整合注释交付 | 对照适用清单交付全部图表与结果；是否重新整合、聚类或注释取决于用户的分析任务，不由交付缺项自动决定 |

缺少表达矩阵、基因集、身份映射等必要输入时，先从项目记录定位；无法解决且会改变结果时再澄清。将未完成或不适用项写明原因，不用推测结果补齐清单。研究代码和产物写入目标项目，本 skill 自包含，不依赖或更新 tools_db。

## 1. 定位分支与实际结果

读取目标项目的规则和结果入口，核实数据集、分析对象、整合流程、主分辨率与有效版本；A/E 单元可从任务索引、摘要及实际执行记录进入，其他项目沿用等价入口。

从真实对象、表格及运行记录确认：细胞 ID 与范围、sample/donor/library 映射、RNA 层、拟合／投影范围、已有坐标／标签／UCell、关键参数与环境。不同流程的输入是否相同须检查成员，不能仅凭方法名判断。原始矩阵只读，正式对象更新按项目约定留存可追溯版本。

完成条件：能够列出本次处理的分支、输入、指定交付与可复用产物；只询问仍会实质改变任务的缺口。

## 2. 按本次交付读取规范

- 整理目录、文件、索引或分支说明时，读取 [目录与结果文件](references/deliverables.md)。每次建立交付入口先读此文件。
- 绘制／检查身份、关注基因、UCell、metadata、技术指标或 DotPlot 时，再读取 [图形与 marker](references/figures-and-markers.md)。
- 目标为人或小鼠肺上皮，且需要选择 subtype/state marker 或评分候选时，再读取 [肺上皮内置字典](references/lung-epithelium.md)，按物种及研究背景选择面板；目录整理不加载字典。
- 绘制／检查 celltype、cluster 的样本数量或比例图时，再读取 [组成图与分母](references/composition.md)。

完整交付按全部适用类别执行；局部任务只读取和应用对应规则。将需求映射到分支、产物与底表路径，优先使用项目已有等价文件，避免重复保存大矩阵或移动仍被后续步骤引用的对象。

## 3. 完成所需导出与图形

按相关参考文件处理命名、分面、数值层、细胞范围和分母。复用中间结果前核对输入和相关参数；实际补算使用项目环境与稀疏／分块操作，保留脚本、参数和输入来源。必要的 marker 排名或组成汇总属于所请求图形的派生计算，不能据此宣称完成了新的条件效应分析。

注释、连续状态、QC 分列保存；证据不足的身份继续保留不确定项。每张新图导出数值底表、顺序／面板信息及来源，图形与索引同时更新。报告实际观察及跨样本支持，整合混合效果、marker 富集或 UCell 高分本身不作为因果证据。

## 4. 核验并交付

对本次产物检查对应参考文件末尾的验收点：细胞和标签映射、数值与底表一致、数量／比例守恒、图表完整性及最终展示尺寸的可读性。已充分验证且输入／实现未变的记录直接复用。

完成条件：用户要求的每个适用项均有可定位产物，未完成或不适用项有具体原因；实际执行范围、参数和证据可追溯。简洁交付入口链接、实际完成内容和影响使用的限制，区分已执行检查与未验证范围，不把目录或格式检查写成科学结果已验证。

本技能提炼自 E20 的交付经验；案例路径、方法组合和阈值不构成其他项目的固定配置。肺上皮内置字典是带来源的候选参考，项目已确认的标签与基因集优先。

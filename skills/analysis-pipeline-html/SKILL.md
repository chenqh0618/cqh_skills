# Analysis Pipeline HTML

让读者理解一项分析如何从输入得到结论。默认使用易懂的中文，面向需要理解研究逻辑、但未必熟悉具体软件的合作者；用户指定的读者、语言、详略和输出位置优先。

## 1. 确定单元与解读模式

从用户指令、当前任务和实际目录确定目标单元，先读适用的项目规则。A/E 项目通常从任务索引、`ABSTRACT.md`、`SUMMARY.md` 和 `AS_RUN.md` 定位；其他项目使用等价记录。目录名称不是采用这套组织方式的前提。仅当目标确实有歧义且会改变内容时询问。

| 模式 | 选择条件 | 展开范围 |
| --- | --- | --- |
| **1 / `unit`，默认** | 未指定模式，或明确要求本单元 | 详细介绍本单元实际分析；依赖的数据和上游结果作为输入概述，说明内容、用途、必要范围与来源，不展开其完整方法。 |
| **2 / `full`，完整流程** | 明确要求模式 2、完整上游，或从**项目原始数据**到本单元结论 | 沿实际使用的依赖追溯，展开必要的上游处理与分析，标注所属单元，组织成从数据到目标结论的流程。 |

“介绍 E01 从数据到结论”本身不改变默认范围。页面开头明确当前模式、目标单元和数据起点。模式 1 也须交代理解结论必需的研究设计、样本范围和独立重复；上游概述不等于省略这些背景。

**仅模式 2**读取 [完整流程的依赖追溯](references/full-pipeline.md)。模式 1 可查上游材料核实输入，但不因此把它们扩写成正文步骤。

## 2. 核实证据，再确定步骤

1. 根据任务指定与实际运行记录定位有效结果版本，核对输入子集、比较关系、单位、关键参数及产物。配置中的默认值或计划值须与实际覆盖参数区分。
2. 读取关键结果表、图及必要代码。实际产物证明结果，代码帮助解释方法；摘要与对话提供线索。关键数字应能回到对应表格、比较名称和筛选范围。
3. 在起草正文前形成步骤提纲：每步解决什么问题、使用哪些输入、做了什么、产生什么输出、由哪个后续步骤使用，以及可引用的证据。按科学问题和数据转换拆分，不按脚本数、文件数或固定章节数凑步骤。
4. 按依赖安排顺序，保留必要的并行分支、汇合与资格判断。选择会改变当前结论的敏感性和失败诊断；单纯运行重试不必逐次叙述。

完成标准：拟讲述的每项关键结果都有可定位证据，流程中的输入和输出能够接上。记录不足的步骤标明已知事实和缺口；无法核实的结论降级或撤下，其他可核实内容继续整理。不要为补齐报告而重新训练、重做统计或增加科学分析。

## 3. 逐步讲清楚分析

每一步都包含以下内容；可以使用短段落、并列卡片或小表，不要求机械一致的字数。

- **背景与为什么做**：当前有什么问题或不确定性，为什么需要这一步，它与前后步骤有什么关系。
- **方法与关键参数**：先解释方法如何帮助回答问题，再交代实际输入、操作及会影响理解和结果的参数。完整命令、软件版本和次要设置放在可展开细节或运行记录链接中。
- **结果与如何解读**：给出实际输出、关键数值或图表中的观察，解释支持的判断、未能解决的问题，以及如何影响下一步。数字注明对象、分母、单位和比较方向。

### 解释性语言

提出步骤、要求或建议时，优先按“问题或目的 → 具体行动”组织句子，让读者先理解为什么，再理解怎么做。对象明确，措辞直白，保留推理所需的衔接，避免过度压缩成方法名串联，也不为解释添加冗长铺垫。

- 例如：“为判断分群是否受到测序深度影响，比较不同深度子集中的分群结果。”这是句式示例，不代表任务已做过该检查。
- 解释结果时写清“图表显示了什么 → 因而支持什么 → 仍受什么限制”，不只重复数值或使用“稳定、显著、鲁棒”等未解释的评价词。
- 在首次影响理解时解释术语；仅对正文实际需要的术语补充简短词表。工具名和基因符号不强行展开。

### 证据强度

涉及统计推断时，区分独立生物学重复与 cell/bin/read 等观测数量，说明推断单位、实际比较及调整因素。优先解释效应大小、不确定性和一致性，p/FDR 保留其检验语境。

区分观察、关联、候选机制与因果证据。把会改变判断的限制放在相关结果旁；阴性、不一致、未执行、失败和仅诊断的结果如实说明。模型运行完成或多种算法使用同一数据得到一致结果，不自动构成生物学验证。背景知识与本次数据发现分开，需要新增外部依据时查可核实的一手来源。

## 4. 用关键图表解释，而不只是列链接

- 选用真正支撑步骤判断的图表，不要求每一步都有图片。关键图和关键限制默认可见，原始大表、补充图及方法细节可折叠。
- 引用图片前实际查看，核对分组、坐标轴、颜色、单位、图例和版本。图旁说明读图顺序、主要观察及解读，来源注明原文件和必要的页码、面板或表格范围。
- 原图保持比例及必要图例；图内字体在最终显示尺寸可读，支持点击放大。PDF 图页可用已有工具转成展示图片；缺图时可从已核实结果表制作简表或重绘同一结果，说明展示转换并保留来源。科学结果图不使用生成式图像替代。
- 来源链接用于回查，不能代替核心证据在页面内的展示。图未核实或缺失时，明确对应结论的证据限制。

## 5. 生成自包含 HTML

执行生成时读取 [构建与检查说明](references/html-build.md)，使用 [HTML 模板](assets/report_template.html) 和随附打包脚本。模板提供通用版式，不含任何项目事实，按当前任务调整步骤与流程图。

页面包括问题与范围、流程总览、逐步解读、结论与证据边界、必要的来源和术语。流程图表示真实的数据依赖，不能把仅供诊断的分支画成主要结论依据。

默认成品在目标单元根目录：模式 1 为 `analysis_pipeline.html`，模式 2 为 `analysis_pipeline_full.html`。用户指定优先。新生成报告遇到同名文件时保留原件，追加 `_v02`、`_v03` 等；用户明确要求更新指定报告时才替换，关键版本遵循项目已有保留约定。

正文、样式、交互和选定图片内置，不依赖联网、全局 skill 路径或项目图像文件才能阅读。原始证据仍保留来源链接和可读路径，并说明这些回查链接需要原项目目录。必要构建材料按项目约定存入本单元的工作目录；源数据、原图和科学分析结果保持只读。

## 6. 验证与交付

1. 对照实际证据检查模式范围、关键数值、参数、比较方向和结论强度；每步具有目的、方法和结果解读，缺失项有明确说明。
2. 用打包/检查脚本检查模板残留、锚点、内嵌资源及本地证据链接。把 HTML 复制到独立临时目录，以 `--portable` 检查核心内容不依赖原目录；来源链接不可携带与页面资源缺失分别报告。
3. 有浏览器时查看桌面、窄屏及打印效果，抽查代表性的长步骤、大图和表格；核对导航、展开收起、图片放大与打印。缺少工具时如实说明未完成视觉验收，不以结构检查替代可读性检查。
4. 交付成品链接，简述所用模式及影响阅读或判断的未验证项。项目约定要求维护阅读入口时，补充现有入口即可；不另建重复摘要或自动发布网站。

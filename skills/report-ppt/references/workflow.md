# PPT 工作流

围绕一个明确的生物信息学分析任务生成正式 PPTX。默认听众为初级专业人员，使用专业但易懂的中文；用户指定的听众、语言、模板、页数和汇报时长优先。按当前问题和证据量安排页数，不为凑结构扩展分析。

## 1. 界定任务并核实证据

- 从调用参数、当前任务及实际输出确定研究问题、比较对象、结果目录和所用运行版本。可使用先前会话留下的结果，只核查与指定任务相关的材料。
- 阅读相关源表、图片、运行记录和必要代码。代码用于了解方法，实际输出用于核实执行及结果；不能仅凭对话或文件名推断数字与图意。
- 核对分组、比较方向、数据子集、关键参数和运行版本；多个版本并存时由任务指定和运行记录定位，不单凭修改时间选取。版本或标识符等关键冲突未解决前，对受影响结果标注未验证，继续使用其他可核实证据。
- 数据概览区分 donor/sample 等独立重复与 cell/spot/read 等观测数量。涉及统计比较时写清推断单位、单位、比较方向和实际使用的关键调整因素。
- 每个关键结论有相应证据；对应页面的备注末尾另列“证据来源”，记录相对成品 PPTX 的源文件路径、必要的 sheet/行列/比较名称或筛选条件。数据或方法页注明所用运行记录；未知信息明确标注。
- 图片缺失但源表可核实时，改用表格或从同一源表重绘。关键证据无法核实时，明确标注未验证或移除对应结论，不能只删图片而保留确定性断言。

## 2. 规划叙事

先在生成脚本中组织每页的标题、正文、图表、讲稿和证据来源；这一规划无需让用户另行批准。

- 默认叙事包含：问题及简要答案、必要的数据与方法、关键结果、限制与下一步。背景、封面、附录和过渡页按汇报需要安排，单任务允许只有一个研究问题。
- 每个结果页服务一个主要判断，可用并列图或多面板图共同回答它；保留对结论有意义的阴性、不一致和不确定结果。
- 标题表达证据支持的要点，明确区分观察、统计关联、候选机制和因果证据。标题已传达结论时无需另加重复 takeaway；封面、方法页和过渡页使用与功能相符的标题。
- 关键结果优先展示已有的效应大小、不确定性和跨样本一致性，显著性指标保留检验和校正语境。影响判断的限制写在对应页面可见位置，不能只放在讲稿里。
- 敏感性分析、统计检验或实验验证只报告实际做过的内容；不为补齐页面自动新增分析。外部方法和机制依据与本次数据发现分开，引用使用可核实的一手来源。

## 3. 图表与讲稿

- 添加图片前实际查看，核对坐标轴、颜色、分组、方向、单位和图注。复用已有结果图时保留可解释所需的图例和坐标，不为美观裁掉关键内容。
- 图与原生表格按表达目的选择：关系、分布和趋势优先用合适图形，精确数值或简短设计信息可用原生表格。图注解释读图所需的语义，已有清晰标注无需机械重复。
- 图片保持比例，图表文字在整页显示时可读，避免通过缩小字体塞满页面。正文通常使用 20–24pt，标题 28–34pt，图注及简短表格通常不低于 14pt；内容放不下时精简或拆页。图内文字也要单独检查。
- 每页保留自然连贯、可直接讲述的 speaker notes，长度随页面功能和汇报时长变化。结果页说明问题、必要方法、图怎么读、结果及限制；封面和过渡页只写相应开场或衔接，不套用结果讲稿模板。
- “证据来源”是备注中单独的核查信息，不混入需要照读的讲稿。数值、单位、结论及来源在页面与备注之间保持一致。

## 4. 生成并保留可更新材料

执行生成时读取 [PPT 辅助工具](pptx-tools.md)，使用其中的轻量 Python 模块。它处理图片比例、中文字体、备注、结构检查和渲染；叙事和具体版式由当前任务的生成脚本设计。

- 优先使用已存在且能导入 `pptx` 与 `PIL` 的环境，依据实际可用字体设置中文字体。本机可用 `Noto Sans CJK SC`；在其他机器检查字体，不假定字体名等于已安装。缺少依赖时优先使用已有文档环境，确需安装则使用独立文档环境，不为做 PPT 改动科学分析环境。
- 默认 16:9；采用用户提供的模板或指定比例时记录该选择，并使用检查工具对应的比例参数。
- 默认成品为 `<结果目录>/report/analysis_slides_<task>_YYYYMMDD.pptx`。结果目录优先用户指定，否则从本任务实际输出推断；无法推断时用当前目录并说明。传入目录已为 `report/` 时直接使用。任务标识优先采用已有 ID，否则使用结果目录名并清理不适合文件名的字符；日期取系统本地日期。
- 默认保留同名文件，新文件追加 `_v02`、`_v03` 等未占用序号；用户明确要求更新指定成品时才覆盖它。用户指定的文件名和位置优先，保留原始数据及分析输出。
- 将任务生成脚本、页面内容及所用 `pptx_support.py` 副本保存在 `report/_build/<成品文件名去扩展名>/`；自定义输出位置时放在成品旁的 `_build/`。生成脚本以自己的位置定位项目输入及输出，不依赖运行时工作目录或全局 skill 路径。
- 在生成脚本开头记录 Python 与相关库版本、字体和输入来源，页面内容与备注集中管理。源图使用相对项目路径；为展示转换或重绘的图片放在该构建目录并记录来源，不改写原图。

## 5. 验证与交付

1. 重新打开 PPTX，使用辅助工具检查文件、比例、标题、备注、图片比例和页面边界；修复错误，对警告逐项判断。结构检查不能证明文字没有溢出、图表可读或科学结论正确。
2. 对照源表核实关键数字、单位、分组与方向，确认页面标题和讲稿没有扩大结论，关键限制可见，备注中的证据路径存在。
3. 有 LibreOffice 和 `pdftoppm` 时渲染全部页面，浏览每页预览，重点检查结果图、多面板图、表格及中文文字。图内文字或排版存疑时查看单页大图。修正后重新生成，仅复查受影响页面及结构检查。
4. 渲染目录使用构建目录中新的空子目录。缺少渲染工具或渲染失败时保留 PPTX 和构建材料，如实说明未完成视觉验收；不能把文件可打开等同于布局已通过。
5. 交付 PPTX 的绝对路径、页数和构建目录，简要说明回答的问题及会影响使用的未验证项。PDF/页面预览默认保留为验收材料，用户需要时再作为额外交付。

# 管理侧

本侧维护科学问题、计划和当前结论。根据当前任务读取相关文件，无需每次整体加载管理历史。

| 文件 | 职责 |
|---|---|
| `PROJECT.md` | 背景、科学问题、目标与实验设计 |
| `RESOURCES.md` | 研究数据及衍生产物的入口、来源、标识、校验范围与已知问题 |
| `PLAN.md` | 主线任务与依赖、进度、当前未决问题 |
| `FINDINGS.md` | 当前有效科学结论、影响科学判断的关键决定与未决问题 |
| `plans/` | 按需编写的科学方案 |
| `history/` | 已被替代或撤回的结论与关键决定，按需读取 |

研究数据事实由管理侧维护；参考数据、工具与环境由执行侧按任务选用并记录。依赖影响方案可行性或解释边界时，按需查项目根 `.project/DEPENDENCIES.md`。

## 规划与执行

计划写清问题、输入、方法与关键参数、预期产物；有必要时补假设、判据、独立重复及阴性结果解释。
用户要求预注册时在观察相应结果前保存可核查版本，并标明后续偏离；普通工作不以预注册或提交作为开工门槛。
背景、数据和实验设计供执行侧读取，计划本身不授权计算。用户本轮已要求执行时，可以向执行者交接目标与范围，无需逐个目录重新申请授权。

## 读取与采纳结果

先从项目根 `TASKS.md` 定位候选 A，读 ABSTRACT 判断相关性，再读 SUMMARY；追踪具体数字时进入对应 AS_RUN、脚本或结果表。
探索任务默认不进入主线表和结论账本。用户要求采纳 E 时直接引用其成果，明确探索性质和证据边界；只有存在证据缺口时才建议另开 A 补做验证。

## 维护当前状态

FINDINGS 的当前条目注明日期、证据性质及依据的 A/E 单元；被替代或撤回的科学结论与关键决定移入 `history/`，保留原因、日期、依据和回链。
环境部署、目录迁移及普通文档调整只更新对应的当前配置；必要的来源、复现或兼容性依据链接已有专项记录。
未知事项写明未知，不把完成状态、模型意见或归档状态视为科学证据。正式审核按用户请求开展，见项目根 `.project/REVIEW.md`。

# 分析与探索的共同约定

## 目标与授权

在用户已授权的科学任务内，可拆分必要 A/E 单元、修复、补图和迭代；委派时传递目标、范围和已知约束。

新分析或实质调整方案时，简要说明输入、方法和预期产物。管理侧方案按用户指定使用；复杂任务可保留简短工作笔记以跨会话衔接。

同一科学问题下的修复、补图和参数敏感性分析可留在原单元。新的问题、比较对象或推断目标需要独立解释或交付时，拆分为新单元。

## 创建与身份

在项目根运行（Python 3.11+）：

```bash
python3 .project/tasks.py new analysis cellTypeProportion --agent codex --question '比较各样本细胞比例'
python3 .project/tasks.py new explore markerSensitivity --agent claude --question '评估标记选择的敏感性'
```

工具分别为 A/E 分配序号，同时检查活跃区和 `_archived/`，冲突立即报错。内容采用小驼峰 `camelCase`；日期为创建日 MMDD，完整日期记入 ABSTRACT。目录与文档主标题一致，例如 `A14_cellTypeProportion_0911_codex`。

后缀固定表示创建 agent，接手不改名。ABSTRACT 的 `created_by` 与 `first_executed_by` 分别记录创建和首次实际执行的宿主（codex/claude，不是模型名）；首次执行前保持 pending，历史无法核实时写 unknown。

开始实际执行时用 `start ID --agent codex`，结束时用 `finish ID --status completed` 或 `failed`；前缀均为 `python3 .project/tasks.py`。状态描述执行进度，completed 不代表科学结论成立。工具不负责启动、监测或终止计算进程。

## 分析依赖

按执行用途区分研究数据与分析依赖：被研究的样本、观测及其衍生产物属于研究数据，清单在 `mgmt/RESOURCES.md`；支持计算或解释的参考数据、工具代码、运行环境属于分析依赖。公共队列用于验证科学结论时属于研究数据，自建索引用于比对时属于分析依赖。管理侧维护研究数据事实；执行侧按任务选择、检查和记录依赖，并维护发生变化的项目依赖入口。

- 方法选择依据科学问题、实验设计和实际数据。参考库提供可复用实现，其流程、脚本和默认参数不限定可选方法；在已授权范围内，可自主采用更合适的库外方法，记录选择理由并完成必要验证。用户指定的方法或方案按其要求执行；发现适用性问题时说明依据。
- 选择或使用分析依赖时先读 [.project/DEPENDENCIES.md](DEPENDENCIES.md) 的相关入口，按任务选择参考数据、工具和实际环境。依赖满足需求且已有验证仍适用时直接复用；仅对新增依赖、尚未验证的功能或受变更影响的步骤进行必要检查。新增依赖、兼容性问题、迁移或重建时，再展开其中链接的记录。
- 参考数据统一配置在项目 `resources_ref/`，按用途分类；下载文件保留来源、版本和校验记录，共享数据集按需链接到该目录并只读使用。项目依赖清单区分配置入口与真实目标；按实际任务核对物种、标识体系及必要的坐标或模型适用范围，处理映射与兼容性。
- 新增依赖在项目环境处理，不直接补装进共享环境；函数加载不能隐式混入外部 R/Python 包。缺失依赖或环境时明确失败，不自动回退旧环境。
- 历史任务按各自 AS_RUN 复现；环境切换或重跑时记录新的执行来源，并保留历史记录。

## 数据与代码

- 本任务的脚本、配置、日志和结果写入自己的单元。复用脚本时保留本地版本或可解析的固定版本引用；使用上游结果时记录真实路径和上游 ID。
- ABSTRACT 的 `upstream` 只登记计算依赖的 A/E ID，形成结论时引用的其他任务放正文。开始重跑前检查上游是否已归档，必要时先恢复。
- 原始数据、关键原始产物和仍被引用的结果保持可追溯；生成覆盖仅用于明确可替换的工作产物。

## 单元内文件组织

分析与探索使用同一约定，文件按用途存放：

| 位置 | 用途 |
|---|---|
| 单元根目录 | `ABSTRACT.md`、`SUMMARY.md`、`AS_RUN.md` 及少量必要说明文档 |
| `scripts/` | 分析、绘图及运行代码 |
| `logs/` | 程序运行日志 |
| `config/`（按需） | 参数、分组和绘图配置；简单任务可直接保留在脚本中 |
| `results/` | 当前有效产物，可按需分为 `figures/`、`tables/`、`objects/`，或按条件、方法组织 |
| `work/`（按需） | 临时试验、缓存和可重建中间文件 |

创建工具默认只建 `scripts/`、`logs/`、`results/`。其余目录在实际使用时创建，不建空占位，也不强制更深层级。`work/` 中的文件不因位置而获得删除授权；供下游复用的对象应列为明确保留的产物，记录路径和计算依赖。迁移已被引用的文件前先核查并同步调用路径，清理遵循 `.project/ARCHIVE.md`。

多个产物版本并存时，用方法、条件或关键参数区分命名，在 SUMMARY 中指出当前有效版本及用途；不靠 `final2`、`latest_new` 等名称判断有效性。

## Git 跟踪范围

Git 跟踪管理文档、规则入口、项目角色、任务与归档索引，以及 `.project/` 的脚本、模板和记录。`.project/DEPENDENCIES.md` 与按需建立的 `.project/environments/` 保存依赖、部署脚本、版本锁定、安装日志、验证结果和迁移快照，纳入版本管理。

A/E 任务整个目录（含脚本、配置、运行记录和结果）、归档任务、`docs/`、`envs/` 与 `resources_ref/` 按根 `.gitignore` 忽略，研究数据实体默认同样忽略。必要的数据元信息例外按项目实际约定维护，保留已有规则。任务文件仍在磁盘保留，复现依据继续按本文件和 AS_RUN 维护。移除跟踪只改变 Git 索引；磁盘清理另按归档约定授权执行。

## 文档分工与读取

说明文档维护当前结构、配置与约束。构建或迁移历史仅保留会影响复现、兼容性、来源判断或后续排障的信息，优先沿用已有专项记录，按需链接；普通文档与组织调整无需逐项记流水账。资源版本、快照日期和验证时间属于当前事实，按需要保留。

| 文件 | 内容与更新时机 |
|---|---|
| `ABSTRACT.md` | 问题、数据范围、状态、主要发现、阅读入口。先用于判断相关性，通常约 150–300 中文字；目标、状态或核心发现改变时更新 |
| `SUMMARY.md` | 当前有效结论、关键数字、主要产物和解释边界，优先一页左右；结论、重要数字或交付入口改变时更新 |
| `AS_RUN.md` | 最终实际方法、输入、命令/脚本/配置、关键版本与随机性信息、重要方法变更；实现或复现方式变化时更新 |
| `PIPELINE.md` | 面向人的流程与方法说明，用户需要教学、汇报或交接时提供 |

这些长度是编辑目标，必要证据可链接至表格和专项说明，不以硬截断丢失依据。ABSTRACT 的 TOML 元数据块供工具读取；保留字段与类型，状态或计算依赖改变后运行 `python3 .project/tasks.py index`。索引可重建，任务本地文档是事实来源。

SUMMARY 维护当前状态，不追加对话或逐次改图历史。字体、配色、画布、图例等纯样式修改只保留最终代码和产物，无需逐轮复制整套结果；仅路径变更时调整产物入口即可。统计方法、过滤阈值、样本范围等变化即使发生在改图中，也需在 AS_RUN 记录原因和影响，必要时同步结论。

AS_RUN 分别记录实际研究数据与分析依赖，固定实际环境、代码和参考数据版本：prefix/解释器、关键软件版本、锁定入口、代码来源，以及资源 ID、版本、项目入口、真实目标和校验范围。参数与具体配置优先链接真实文件；项目依赖清单不替代任务运行事实。失败重试只保留会影响解释、复现或避免再次踩坑的部分。跨会话工作笔记在完成后合并必要信息，过时草稿可按归档规则整理。

先查 `TASKS.md` 或检索候选 ABSTRACT，相关才继续读 SUMMARY；需要方法、重跑或核验时进入 AS_RUN、代码和具体结果。纯绘图修改直接读取相关脚本和图，不重新通读所有分析历史。

## 完成与交付

完成或失败时，按上述更新时机维护任务文档，记录实际结果、未解决限制和复现入口。日常验证由执行者完成；审核流程见 `.project/REVIEW.md`。

# Project Init Loose

为指定项目铺设 `mgmt/`、`analysis/`、`explore/` 和项目根 `_archived/`。管理计划不自动触发执行；用户授权的科学任务内可自主拆分工作。初始化负责组织约定和背景清单，科学结论由真实分析产生。

## 初始化

1. 从用户指令或明确的当前项目上下文确定目标目录，解析真实路径。只有目标无法确定时才询问。
2. 检查现有规则、背景文档和数据入口。读取足够说明研究背景、数据位置和样本设计的信息；大型数据只查清单、元数据和浅层结构。
3. 在初始化时明确分析领域、项目类别（`lightweight` / `complex`）和环境方式（`shared` / `project`），记录依据。类别由维护周期、依赖变更和交付要求决定，不仅看数据量；环境方式独立选择，用户已有选择优先。轻量且依赖满足时可共享，长期/复杂或需要新增依赖时推荐项目环境。根据上下文可以确定时直接填写，只有无法判断且会改变方案时才询问。
   scRNA/snRNA 项目读取 `/public/data/cqh_data/proj_sync/tools_db/scRNA/docs/PROJECT_USAGE.md`；参考库不可访问时记录缺口，不静默切到旧库。其他领域按其实际参考库处理，不自动加入 scRNA 依赖。
   运行脚手架（Python 3.11+，仅标准库）：

   ```bash
   bash "<skill目录>/scripts/scaffold.sh" "<项目绝对路径>" \
     --domain scrna --project-class lightweight --env-mode shared \
     --reason "任务短期且已验证共享依赖满足需求"
   ```

   上述是轻量 scRNA 示例，参数应按实际任务替换；`--reference-root` 可指定实际参考库。原不带可选参数的调用仍可生成待分类骨架，使用本 skill 完成初始化时须补齐选择或写明具体未决项。
   脚本先检查所有受管理路径的冲突，再创建骨架；已有项目按 [MIGRATION.md](MIGRATION.md) 处理。不要通过删除已有文件绕过冲突。
4. 依据文件与用户信息填写 `mgmt/PROJECT.md`、`mgmt/RESOURCES.md`、`.project/DEPENDENCIES.md` 和根 `CLAUDE.md`。尚缺背景或数据时可以完成骨架，写明未知；只有缺失项妨碍当前要求时才询问。跨条件分析的推断单位与独立生物学重复须明确或标为待确认。
   背景与类别依据填入 `mgmt/PROJECT.md`，研究数据事实填入 `mgmt/RESOURCES.md`，当前参考数据、工具代码与“任务用途 → 环境 → 启动命令”填入 `.project/DEPENDENCIES.md`。文件分工与执行约定见生成的 `.project/WORKFLOW.md`。
   依赖回填实际路径、版本、状态和验证范围；未部署的环境标 planned，安装和验证后按已有证据更新。必要的来源、校验、锁定、补丁与验证详情链接已有专项记录，日常入口描述当前配置。仅初始化记录参考数据配置，不执行软件安装、资源下载、批量链接或创建空资源目录。
5. 若有既有规划文档，保留原件，在 `mgmt/PLAN.md` 建立入口或整理有依据的任务与状态。保留科学约束和真实进度；旧机制不再适用时解释差异，不凭关键词删除约束或把全部状态重置为待做。
6. 检查生成文件、软链、背景清单和 [Git 跟踪范围](templates/project/WORKFLOW.md#git-跟踪范围)。共同忽略规则由 `templates/root_gitignore` 的标记段维护，脚手架读取该段，为已有 `.gitignore` 补缺并保留自定义规则；已有文件移除跟踪按 [迁移说明](MIGRATION.md#git-跟踪策略) 处理。若用户要求提交，或当前是没有既有提交的新仓库，按授权范围明确暂存路径；默认只提交本次生成、回填的文件，用户明确指定的其他修改可一并提交。
7. 简述生成位置、已填事实和仍未知的信息。用户本轮同时授权分析时可继续执行；仅初始化时完成骨架即可。

## 规则来源

- 项目级指令分两级：根提供项目背景摘要、读取入口和通用科学要求；`mgmt/`、`analysis/`、`explore/` 保留各侧职责与必要约定。各目录内的 `CLAUDE.md` / `AGENTS.md` 共用一份正文。
- 科学要求内嵌于根模板，生成后按项目需要维护。分析和探索的执行细节集中在 `.project/WORKFLOW.md`，相关规则不在上下文中或已变更时补读；归档、恢复、清理查 `.project/ARCHIVE.md`，正式审核查 `.project/REVIEW.md`。
- Claude 与 Codex 的项目角色文件只声明职责并指向对应规则，缺少相关指令时补读。使用当前宿主提供的委派能力，角色不构成强制执行流水线；模型随会话继承。
- `ABSTRACT.md` 筛选相关任务，`SUMMARY.md` 给出当前结论，`AS_RUN.md` 提供复现入口；教学型 `PIPELINE.md` 按需。详细规则由生成文件负责，此处不重复。

本 skill 的修改只影响以后生成的项目。已有项目更新需按迁移说明显式选择范围；不批量重命名、归档或清理科研项目。

# 已有项目的选择性迁移

本次 skill 更新不自动修改任何已有项目。先选定项目和迁移范围；目录改名、归档或产物清理分别按实际授权处理。没有批量覆盖式 --upgrade。

## 1. 合并项目规则和工具

检查目标项目的根/三侧 CLAUDE、AGENTS、项目角色及自定义科学约束。保存可审查的原版本（已有 Git 可用 diff/提交，未纳入 Git 的文档保存小范围备份），避免复制全部数据和结果。

可在临时空目录运行本 skill 的 scaffold，作为候选文件来源。合并时把候选根文档的规范根改为真实目标路径，不直接复制含临时路径的文档。保留项目背景、数据事实、计划、当前结论和自定义约束。

- 合并根与三侧入口，加入 .project 的共同规则、共享 templates 和 tasks.py。
- 建立 _archived/analysis、_archived/explore，补归档读取规则。
- 合并 Claude/Codex 角色入口；同名自定义角色先审查差异，不直接覆盖。模型和权限继续由实际宿主配置决定。
- 已有 AGENTS/CLAUDE 内容不同时先合并有效规则，再选择共用正文；不强制替换成软链。
- .gitignore 中补入 .project/tasks.lock 和临时文件规则。
- 若已有 TASKS.md 或 _archived/INDEX.md，先保留其有用信息并解决命名冲突；工具拒绝覆盖非生成索引。

工具只扫描活跃区与归档区的一层任务目录。已有其他归档位置、重复 ID、任务软链或依赖别名时先核实并统一映射；不把它们当作空任务集继续分配编号。

## 2. 按需补任务文档

保持已有目录名和路径；不批量改成新命名规范。优先处理即将接续、需要检索或需要归档的任务，其余可以逐步补充。

1. 依据实际材料新增 ABSTRACT，保留任务原名为标题。模板来自 .project/templates/ABSTRACT.md。
2. 拆分旧 SUMMARY：当前有效结论与关键产物保留在 SUMMARY；最终实际方法及有科学影响的变更移入 AS_RUN。旧流水账中必要证据保留链接，可回溯原版本；不要伪造缺失的方法信息。
3. 纯字号、配色和排版历史不再逐轮追加。已有 PIPELINE 可以保留，后续仅在交付或方法解释需要时维护。
4. 本单元内产物入口优先改为相对路径；历史脚本与外部数据路径先保留，不做批量字符串替换。

新建或继续处理任务时，按 `.project/WORKFLOW.md` 的文件组织约定存放新增文件。默认使用 `scripts/`、`logs/`、`results/`；`config/`、`work/` 及结果子目录按实际需要创建。已有文件不为满足目录外观批量搬迁。确需调整时先核查脚本、文档和下游调用路径，在授权范围内迁移、更新入口并做相应验证；历史路径在此之前保留。

整理后让 SUMMARY 明确指向当前有效产物，AS_RUN 保留实际代码、配置和重要中间对象入口。临时文件的位置不代表删除授权；已被引用的对象即使位于 `work/`，仍按需保留并记录依赖，清理另按归档规则处理。

ABSTRACT 的工具元数据采用一个 TOML 代码块，例如：

```toml
id = "A04"
status = "unknown"
created_at = "unknown"
created_by = "unknown"
first_executed_by = "unknown"
upstream = []
```

id 取真实目录 ID；状态依据现状填写 planned/running/completed/failed，无法核实时保持 unknown。upstream 填计算依赖的本项目 A/E ID；不得将未知依赖猜成空数组，上例仅示意格式，必须核查后填写。外部项目依赖在正文记录真实路径并单独检查。创建日期和原 agent 无证据时保留 unknown，不根据文件 mtime、文风或当前宿主推断。

缺少 ABSTRACT 的旧单元在索引中标记 legacy，不会被自动“补全”；发现 ID/位置/依赖不一致时工具明确失败。任务元数据和目录名称核对后运行：

```bash
python3 .project/tasks.py index
```

## 3. 归档和管理历史

归档前遵循 .project/ARCHIVE.md，确认已停止、理由明确及当前计算依赖已解决；先预览再迁移。若项目根已整体搬迁，先核对历史绝对路径，工具不会静默修复 original_root 不匹配。归档后的重跑先恢复原位。

FINDINGS 逐步整理为当前有效结论；被撤回或替代的原内容保留在 mgmt/history 中，附日期、原因、依据和回链。管理历史整理不删除对应的科学证据。

清理大对象是单独任务。先核算选定文件的体积与依赖，再依据用户授权执行；保留必要记录、代码、配置与证据。清理后更新归档 retention 和 AS_RUN 的复现限制。

## 4. 验证所选范围

核对根路径与角色入口，重建索引，检查所迁移任务的 ID、状态和计算依赖。可对一个无活动依赖的小任务验证预览与恢复；不要为了验证组织结构重跑全套组学流程。

## 环境选择记录（scRNA_v2 关联）

此更新仅影响以后初始化的项目。已有项目按用户指定范围，在 PROJECT 中补领域/类别/理由，在 RESOURCES 中补 shared/project、实际环境prefix/版本/验证范围和资源引用；由既有记录核对，不能把历史任务改记为使用 v2。只新增读取入口，不自动搬迁数据、重建环境或替换脚本。未知的历史环境写 unknown。

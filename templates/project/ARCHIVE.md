# 归档、恢复与空间清理

归档迁移到项目根 `_archived/analysis/<原名>/` 或 `_archived/explore/<原名>/`。任务 ID 和名称保留。归档内容用于历史查阅，恢复原位后再修改、继续分析或重跑；不要从归档位置直接执行历史脚本。

## 什么时候归档

用户明确放弃、明确被其他任务替代的已停止任务，可以在授权范围内自主归档；仅凭时间久或一次失败只能提出候选。先确认没有进程继续写该单元，并检查当前任务的计算依赖。结论引用不等于计算依赖。

已登记的 planned/running 下游会阻止迁移。未登记依赖、外部项目引用和后台进程需要执行 agent 检查：结合 ABSTRACT、相关脚本/配置和当前作业信息核查，不依赖旧 GRAPH 或全文文本命中来直接下结论。无法解决正在使用的路径依赖时暂缓迁移该任务。

## 预览与迁移

在项目根执行（Python 3.11+）：

```bash
python3 .project/tasks.py archive A03 --reason '已被 A14 替代' --replacement A14
# 完成运行状态与依赖检查后，执行 agent 加 --checked 表示检查已完成：
python3 .project/tasks.py archive A03 --reason '已被 A14 替代' --replacement A14 --apply --checked
```

工具默认只预览，--apply 才迁移；--checked 表示 agent 已完成检查，不是另一次用户审批。任务须已停止且状态明确；completed/failed 或用户明确放弃的未执行 planned 任务均可归档。旧任务没有 ABSTRACT 时先按迁移说明补真实元数据，不猜历史状态。

工具检查编号、状态、已登记计算依赖和目标冲突，使用同文件系统 rename，不复制大对象，不覆盖目的目录；跨文件系统会明确失败。迁移更新 ABSTRACT 的状态和归档信息：原路径、日期、原因、替代任务、上次状态和产物保留情况。历史脚本与原始结果不做全局路径替换。

日常 `TASKS.md` 排除归档；`_archived/INDEX.md` 提供历史入口。索引只从任务本地摘要生成，不另维护一份结论账本。阅读归档产物时将历史原路径映射到其归档位置；历史路径表示当时的运行环境，不承诺迁移后可直接执行。

## 恢复

```bash
python3 .project/tasks.py restore A03
python3 .project/tasks.py restore A03 --apply
```

恢复到记录的原目录，已有同名路径时失败，默认不建立兼容软链。恢复后核对依赖、保留情况和环境，再开始计算；归档与恢复成功不等于已证明可复现。

## 回收空间

移动目录不减少磁盘占用。用户提出清理需求后，再列具体文件或目录、预计释放空间、是否被依赖、重算成本及保留理由；取得覆盖这些文件的授权后执行，不重复申请已有授权。

保留 ABSTRACT、SUMMARY、AS_RUN、必要代码配置和证据入口；原始数据、关键原始产物与仍被依赖的对象不属于默认清理候选。优先考虑明确过时的可替换图稿、可重建缓存和低成本中间产物，逐项判断。清理归档内部可再生产物属于维护操作，无需恢复整个任务；清理后更新归档信息的 `retention`，必要时在 AS_RUN 标明缺失对象、重算入口和复现限制。

辅助工具不自动删除或压缩科学产物。不要仅因文件扩展名、大小或时间旧就删除，也不为纯样式修改逐轮创建完整备份。
